# 多场景分批交付

## 默认节奏

整套默认约 18 张独立图片，按实际需求调整为四至六个场景、三批交付，每批 4–6 张。原 Logo 属于输入素材，辅助图形、载体应用和场景效果按实际独立图片计数；文字说明单独保留。

| 批次 | 重点 | 常见分配 |
|---|---|---|
| 第 1 批 | 视觉基底与高频使用 | 1 张辅助图形、4 张核心载体应用、1 张场景效果 |
| 第 2 批 | 经营与传播扩展 | 两个适用场景，各 3 张独立图片 |
| 第 3 批 | 活动、礼赠或空间补充 | 再选两个适用场景，各 3 张独立图片 |

这是规划起点。用户指定的行业、用途、数量、阶段与预算决定实际路线图。资料就绪后先完成首批，后续批次随用户的续接指令推进；用户明确要求连续执行多个批次时，按其指定范围推进。

## 品牌与进度记录

在当前聊天按设计主题保存：品牌及行业、Logo 资产 ID 与版本、主辅色原值、准确文案、固定设计约束、已采用的辅助图形资产，以及各批场景、载体、状态和真实产物引用。每项使用稳定编号，例如 B1-01、B2-01。

路线图包含整套候选批次及用途。执行清单包含用户本轮要求制作的条目；未来批次保存为下一步建议。继续时先核对真实已完成项与用户新要求，再选择下一批。品牌资料来自本项目中对应的用户记录，修改按最新明确要求更新。

## 小居 中的计划范围

- 用 `conversation_memory_read` 读取品牌资料、已采用决定和批次进度；用 `conversation_memory_update` 保存带来源的标准色、行业和设计约束，原 Logo 标注 logo、主视觉标注 key_visual、专项图形标注 specialist。生成图保持 artifact 身份，用户采用后更新其用途与依据。选择本批所需记忆，并按交付项绑定实际图片。
- `design_plan.deliverables` 首轮列入当前批次条目。后续批次的场景、编号、载体和数量写入 `deferred`，并在最终回复中解释为“下一批建议”。每条控制在 350 字以内。
- 用户回复“继续”时，先读 `design_plan`、`canvas_read` 与当前项目对话。前一批有缺项时先补齐；前一批完成后，保持原交付项 ID 和验收条件，把选中的下一批条目追加到清单，保留原 scopeId 对应的真实资产关系。
- 已完成条目保留为累计进度，新增条目作为本批工作。将本批从 `deferred` 移入执行清单，其余批次继续保留为下一步建议。场景、图案或标准色变化时更新对应用户决策与相关条目。
- 同批图片通过 `deliverable_ids` 绑定条目；独立项使用 `generate_batch`。同一图形参考保持真实资产引用，需要新母版的条目通过 `dependsOn` 关联。
- 本轮明确数量以服务端交付约定为准。整套路线图和本批数量分别表述，例如“整套建议三批，当前执行第一批六项”。验收按当前执行清单，通过本轮节点缩略总览统一进行一次；不逐项读取高清原图。

## 每批结束的提示

用简短自然语言说明四件事：本批完成项、累计进度、下一批内容、可回复的操作。具体名称和数量来自已保存路线图。

示例：

> 第 1 批已完成 6 项，当前累计 6/18 项。已交付辅助纹样、咖啡杯、杯套、外带袋、封口贴和外带场景。
>
> 建议第 2 批延展门店与线上传播：菜单、门头、服务卡、品牌头像、主页封面、上新宣传图，共 6 张。
>
> 回复“继续”即可制作第 2 批；也可以说“下一批改做礼赠场景”或“先调整杯套”。

本批有待修正项时报告实际完成数量及具体项，先处理该批。整套完成后按场景汇总产物链接，将新增方向作为可选建议。
