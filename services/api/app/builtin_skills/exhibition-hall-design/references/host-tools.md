# 在不同 Agent 中执行

在 Codex 中使用当前图像生成工具制作或编辑图片，使用文件工具保存墙面台账与说明。每项视觉成品保存为独立 PNG/JPEG/WebP。

## 小居 / 朗居工具映射

- 用 `context_read`、`conversation_read`、`canvas_read`、`asset_search` 和 `asset_inspect` 查找并实际查看空间三维图、尺寸图、参考图和已有整体效果；用 `conversation_memory_read` 读取本聊天已确认的墙面编号、整体母版资产 ID/版本、墙面到母版视角的对应关系、视觉锁定项和阶段进度。记忆只帮助定位，生成前仍需核对真实资产。
- 对引用的 DOCX、PPTX 或 PDF 先用 `document_read` 分页读取正文结构和图片目录；只查看与当前墙面内容有关的子资源，使用 `document_part_inspect` 实际看图。只有确认要把该图片用于生成输入时才用 `document_part_promote`，并保留来源文档与定位。
- 用 `canvas_create_text` 保存墙面台账、内容映射、素材状态和待确认项；整体方向确认后补充“视觉锁定表”，至少记录母版资产 ID 与内容版本、每个 `wallId` 对应的母版视角、锁定项、允许变化项和冲突状态。不要把待确认、概念示意或参数未知提示写进生成图像的像素。
- 用 `design_plan` 保存当前阶段交付清单。第一阶段只包含墙面台账和整体效果图；逐墙效果写入 deferred 或后续批次。收到明确继续指令后，再把用户确认范围内的逐墙图加入当前批次。第二阶段每个墙面交付项的 `inputs` 都声明同一已确认母版资产为 `reference`，并声明该墙对应的底图为唯一 `layout` 输入；不得只写“风格一致”而不绑定真实图片。只有各墙输出画幅相同时才可用 `visualSeries` 记录共同锁定项，且它不能替代逐项真实输入。
- 用 `generate_image` 生成整体或单墙效果。对需要施加设计的三维底图或墙面底图填写 `reference_analysis.mode=edit` 或 `layout` 并列明几何保留项；已确认整体母版必须填写 `mode=identity`，`use` 写明“从该母版展开指定墙面而非重新设计”，`preserve` 写全视觉锁定表。原始风格图只在第一阶段使用 `inspiration`；进入逐墙阶段后不得让它越过整体母版重新主导风格。真实展品、Logo 和文档图片继续使用 `identity`。设置 `output_mode=create`，所有结果新建节点并保留原图。
- 调用 `generation_reference_check` 前核对每个墙面操作的输入：母版资产 ID/版本必须完全相同，墙面底图和 `wallId` 必须一一对应。通过后才可用 `generate_batch` 批量执行独立墙面；每张图用 `deliverable_ids` 绑定实际墙面编号。连续画面的相邻墙可增加接缝参考，但不得用上一张生成图替换整体母版。
- 需要补充风格方向时先用 `reference_search`、`reference_inspect`，再由主 Agent 用 `request_reference_selection` 让用户选择；用户已经提供明确风格图、明确跳过或已确认整体效果时不重复选图。
- 用 `conversation_memory_update` 保存稳定墙面编号、确认的整体母版资产与版本、墙面对应关系、视觉锁定项、当前阶段及累计完成墙面。文档内容和墙面分配是项目事实，不能仅凭记忆替代真实来源读取。

## 生成与确认边界

- 第一阶段整体效果生成成功后直接交付并结束本轮，不自动调用逐墙生成。
- “继续”“下一步”“整体方向可以，做各墙”等明确表达才进入第二阶段；普通提问、下载、查看图片或未回复都不算确认。
- 用户修改某一面墙时，把该墙原图作为编辑来源并新建结果，同时继续传入整体母版；若修改触及共享视觉锁定项，先更新整体母版而不是单墙自行分叉。
- 生成后由系统基于本轮节点缩略总览统一审查一次，逐项对照母版的配色、材质、图形、模块比例、陈设和灯光。锁定项有差异、母版未实际进入输入或墙面映射不清时，不把该项标为完成，也不静默改用提示词重生成；保留真实结果并报告待核实。仅确有必要或用户明确要求局部检查时读取对应图像细节，不逐图自动修复复审。
