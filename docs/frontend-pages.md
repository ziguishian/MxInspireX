# 前端页面与组件边界

核心页面使用独立 Vue 页面组件和路由。数据仍由 Vue 响应式渲染；页面拆分解决职责、导航和维护问题，不把数据写成静态页面。

## 页面划分原则

统一下拉控件由 `mx-theme.css` 管理圆角、菜单背景、选项状态和箭头留白。支持 `appearance: base-select` 的内置浏览器使用主题化原生 picker，保留键盘、搜索定位及表单行为；旧浏览器保留主题化触发器和系统菜单。`ThemeSwitcher.vue` 将深色、浅色、跟随系统收进单一按钮，使用原生 popover 处理外部点击和 Escape，并支持方向键切换焦点。首页底部不再展示企业署名。

具有独立用户目标、需要可收藏地址、离开当前项目仍有意义的内容，独立成页。依赖当前选中对象、短暂配置或操作后返回原任务的内容，保留组件或浮层。页面负责自己的检索、筛选和空状态；共用的数据访问、任务进度和草稿生命周期由应用服务协调。一个项目的对话和画布属于同一工作区，不为每种节点额外建立页面。

## 哪些内容独立成页

| 地址（普通路径，无 `#`） | 页面组件 | 职责 |
| --- | --- | --- |
| `/` | `HomePage.vue` | 创建任务、共享输入框的首页容器 |
| `/projects` | `ProjectsPage.vue` | 项目搜索、筛选、触底加载和画板预览 |
| `/projects/:projectId` | `ProjectWorkspacePage.vue` | 一个项目的对话和无限画布 |
| `/assets` | `AssetsPage.vue` | 跨项目素材浏览、筛选、引用 |
| `/knowledge` | `KnowledgePage.vue` | 用户上传的知识文档及管理 |
| `/schedules` | `SchedulesPage.vue` | 定时任务管理 |
| `/settings/:section` | `SettingsPage.vue` | 用户中心、外观、模型与连接、路由与积分、能力组件和关于；旧 `/account` 跳到用户中心 |
| `/settings/help` | `HelpPage.vue`（嵌入设置） | 设置导航最下方的使用说明；右下角问号直达，旧 `/help` 自动跳转 |
| 未知地址 | `NotFoundPage.vue` | 无效链接的明确反馈和返回入口 |

这些页面有独立目的，需要直接打开、刷新和浏览器前进后退。路由懒加载，工作区的画布依赖不再随所有页面一起加载。网页使用 HTML5 History 路由；桌面本地文件使用内存路由，刷新时恢复窗口内部的目的页，避免尝试读取不存在的本地目录。两种环境均不新增 `#` 路由。

## 哪些内容保留为组件或浮层

- Provider 设置位于 `/settings/text` 独立页面；头像先显示概览小卡片，点击设置进入用户中心。退出设置可以回到原工作区。
- 模型切换、风格选择、上传和引用预览属于当前输入操作，不建立独立页面。
- 画布节点、连线、节点参数和生成输入组件属于项目工作区，不把每个节点变成页面。
- 对话与画布属于同一项目上下文，工作区内部切换不重新建立任务观察器。
- 项目画布隐藏全局左侧导航并占满工作区，用户头像移到右上角，概览卡片在头像下方展开。返回首页按钮在对话展开时位于对话框左上角，收起时位于左侧竖向控件最上方；项目加载期间也保留返回入口。退出画布后恢复全局侧栏和左下角头像。
- 项目对话栏收起后，Home 固定在左上角，竖向画布工具栏（新增、选择、拖动画布、整理、撤销/重做）在左侧中央，当前吉祥物头像在左下角。头像圆角和底部间距与右下角帮助按钮保持一致；点击头像恢复对话。收起/展开通过 Vue Transition 向左下角缩放淡出/展开，复用 `useMotionPolicy` 尊重系统/应用减少动画。面板只隐藏，保留已挂载的输入框、草稿、附件和对话滚动位置；隐藏期间不可聚焦，工具栏间的留白可直接操作画布。画布自动取景避让竖栏，窄屏节点输入区收窄并换行，保持文字尺寸。窄窗口对话框顶部为右上角用户头像预留空间。
- 撤销/重做以服务实际保存的字段为准，避免自动排版后的坐标与历史预期不一致；只记录本次编辑字段，不把并发 Agent 产物纳入回滚。上传新增节点同样记录历史。撤销后重做以该次保存回执更新预期值，支持 Ctrl / ⌘ + Z、Ctrl + Y 和 Ctrl / ⌘ + Shift + Z。失败通过全局提示显示，对话收起后仍可见；无可用历史时按钮禁用并提示原因。快捷键说明仍保留在右下角画布操作入口。
- 创建节点期间禁用撤销/重做，成功后再按保存回执登记历史；同一应用会话内切出并重新打开项目会保留历史，按 API 地址和项目隔离，最多保留最近 8 个项目各 40 步。历史只驻留内存，刷新页面或重启应用后重置，不把画布内容写入 localStorage。

`App.vue` 保留应用外壳、共享草稿、API/任务状态协调和全局浮层；各页面通过 `features/pageServices.ts` 中按页面划分的类型接口读取所需数据、调用命令。页面自身持有筛选、触底加载等局部状态。没有向页面传递整个 App 实例，也没有新增系统级 Agent 记忆。

共享的 `PageHeader`、`SearchField`、`EmptyState`、`InfiniteScrollStatus`、`MasonryGrid` 和 `ProjectCard` 负责稳定的 UI 结构。项目、资产和参考库分批渲染并在接近页面底部时继续加载，滚动超过一屏后显示共享的回到顶部入口；资产和参考图片按原始比例进入最多四列的响应式瀑布流，不设置统一卡片高度或宽高比，横图、方图和长图均完整展示。资产缩略图按渲染批次直接加载，进入视口附近后会检测长时间未完成的请求，并对临时失败做有限重试；网络返回后继续等待图片解码，期间以保留尺寸的流光骨架和加载标识占位，解码完成再渐显原图。资产和参考卡片默认完整展示预览，鼠标悬停或键盘聚焦时才显示透明渐变信息层。资产收藏按钮和项目操作入口也随交互显现。信息层使用合成器处理的透明度与三维位移动画，不在交互时重新模糊底图。

`ProjectCard` 使用项目首个生成资产作为封面，复用 `LibraryAssetThumbnail`。默认只显示封面，悬停或键盘聚焦时标题和描述从封面底部向上浮现；描述优先采用项目需求，缺失时使用项目摘要。信息层使用半透明渐变与固定 12px 背景模糊形成毛玻璃，顶部柔和过渡，保留封面颜色与轮廓；只对透明度和位移执行动画，减少动画模式下直接显示。标题和描述各最多两行，标题为右上角菜单留出位置；菜单位于裁切区域外，重命名时信息层保持可见。无悬停能力的设备直接显示信息，480px 以下改为单列，避免文字裁切；深浅色主题共用毛玻璃衬底与浅色文字。

首页和项目对话复用输入框，由 Teleport 放入各自容器；草稿按首页或项目 ID 独立保存到 IndexedDB，包含文字、附件与引用。首页 小居 除点击反馈外，会在凌晨与少量固定时刻展示每日一次的本地提示；这些提示不创建任务。

每次提交保存稳定 `requestId`，响应丢失后重用原 ID。消息队列在任务成功且产物已保存后推进；真实失败、未完成项、未知请求、待补充需求或参考仍暂停。已删除审查状态、质量提示和“按建议创建修订”入口，历史审查结果不再显示。用户可直接在对话中描述修改要求。

首页输入框上沿使用山云 IP 的六表情透明雪碧图，身体由输入框图层遮挡；保留点击对白、定时提示和减少动态效果支持。素材路径、原始参考及生成提示词见 [lumo-composer-assets.md](lumo-composer-assets.md)。

## 导航与异步数据

`features/navigation/useWorkspaceNavigation.ts` 协调路由和现有任务状态：

- 项目目录加载完成后才判断项目链接是否失效，避免慢请求导致误跳转。
- 浏览器直接访问 `/` 始终进入首页，直接访问子页面时不会被上次打开的项目覆盖。
- 旧书签 `/#/projects/id` 自动替换为 `/projects/id`，不新增一条历史记录；普通页内锚点保持原意。
- 项目页面只渲染与路由中的项目 ID 相符的画布，避免目录加载过程中短暂显示上一个项目。
- 从素材库或项目返回首页时恢复首页未提交草稿；切换项目保存并恢复对应项目草稿，成功提交后清空本次已发送内容。
- 浏览器前进后退、页面命令和项目切换不相互重复推入历史记录。
- 素材和知识页区分加载、失败、空库和筛选无结果；刷新失败时保留已读取数据并提供重试。

## 输入与引用组件

`features/composer/references.ts` 解析完整引用 token，编辑器内渲染可预览缩略图；序列化仍保留稳定的资产/文档 ID。删除引用会同步移除发送上下文。普通文档显示类型卡片，图片显示实际预览。`ReferencePreview.vue` 在页面顶层展示悬停或键盘聚焦预览，避免父容器裁切。

已发送消息由 `UserMessageContent.vue` 显示同主题的小缩略图或文件类型卡片，悬停查看名称，点击打开预览。`messageReferences.ts` 根据每条任务保存的引用信息恢复文件和编号，不依赖当前输入框；历史消息刷新后仍对应原文件。任务接口只返回引用的 ID、名称、类型和所属项目等必要信息，项目附件使用受路径边界保护的内容接口。

`StylePicker.vue` 使用六种风格的同主题参考图，复用一张 3×2 雪碧图，通过真实图片元素裁切显示。图片按文档路径加载，兼容桌面 `file://` 和网页深链接，提供加载状态及失败重试。点击卡片仍写入现有风格配置；预览素材和生成提示词见 `style-sprite-prompt.md`。项目输入框与对话面板的左右下边缘对齐，不另加一层背景。

## 验证

模型菜单由 `AnchoredPopover.vue` 按触发按钮与可视窗口的实际距离选择上方或下方，在空间不足时限制高度并滚动。菜单传送到页面顶层，避开输入框裁切；窗口缩放、祖先滚动及菜单内容变化都会更新位置。桌面版预留标题栏空间。构建两种版本后可用 `npm run test:model-popover` 验证定位与关闭交互。

构建桌面版与网页版后，`npm run test:style-picker` 在隔离 Chromium 中检查六种风格的图片裁切、桌面文件路径、网页深链接、选择后重开、窄屏布局及图片失败重试。

Agent 新回复由 `ReplyTypewriter` 缓冲网络分块，按 Unicode 字符连续显示，并根据来字速度调整节奏。`AgentMarkdown` 仅在内容快照改变时解析 Markdown，用稳定的 Vue 节点更新文字；完成后继续显示尚未打出的文字，停止和错误立即展示。历史回复、后台页面以及系统减少动态效果模式直接展示已收到内容。滚动只在用户停留底部时跟随，`npm run test:reply-typing` 使用隔离 Chromium 和模拟回复检查这些交互。

公开进度记录在任务进行中默认展开，标题显示“思考中”；用户可手动收起。结束后自动收起，按结果显示“思考完成”“思考中断”或“已停止”，仍可再次展开查看。

`npm run typecheck` 覆盖 Vue 模板和桌面代码；`npm test` 包括路由加载时序、历史导航、草稿保留、引用解析与发送上下文测试；`npm run build` 检查页面分块和桌面编译。

后端 `services/api/tests/test_knowledge_preview.py` 验证知识库图片内容接口及路径边界。界面检查覆盖上传缩略图、编辑器引用、风格浮层和工作区输入容器，不需要触发付费生成。

## 网页与桌面构建

- `npm run dev:web`：Vite 网页和本地 API，首页为 `http://127.0.0.1:5173/`，API 使用 `http://127.0.0.1:8765/`。
- `npm run dev`：Vite、Electron 与桌面 sidecar；普通浏览器打开 Vite 页面时与 Electron 固定共用端口 `8765`。若端口已被占用，开发启动会明确失败，不会静默切换到浏览器无法发现的随机端口。
- `npm run build:web`：网页产物写入 `dist/web`，资源以站点根路径加载。
- `npm run preview:web`：预览网页产物，支持直接访问和刷新子页面。
- `npm run build`：保留桌面产物 `dist/renderer` 和 `dist/desktop`，资源以本地文件相对路径加载。

网页部署需将前端页面的未知路径回退到 `index.html`，同时保留 API 与静态资源的真实 404。Vite 开发与预览服务已提供页面回退。部署在子目录时使用 Vite 的 `--base=/studio/`，路由与资源基路径随构建配置一致。

Nginx 根路径部署示例（本地 API 独立提供，不放在该静态目录中）：

```nginx
root /path/to/dist/web;
location /assets/ { try_files $uri =404; }
location / { try_files $uri $uri/ /index.html; }
```

`npm run test:page-navigation` 使用独立浏览器和模拟 API，验证网页生产包的子页面刷新、旧地址迁移、前进后退、桌面本地包导航和刷新恢复，不写入用户项目数据。


## 工作清单、运行中补充与请求核对

- `messageQueue.ts` 统一处理流式结束、重进项目和手动续发。队列不再等待质量审查；生成失败、缺项、未知结果、需求/参考待补充、取消和未应用补充仍暂停。
- 运行中输入框明确选择“补充当前任务”或“加入下一项”。当前补充支持文字，附件/资产/技能需作为下一项提交。`task_updates.py` 独立持久化补充并按请求 ID 去重，不受任务输入快照重写影响。模型判断前 `task_updates.mjs` 读取全部补充并注入实际模型输入；网关比较补充版本，阻止旧版本的新工具调用。已经提交的请求不撤销、不重发。界面区分等待应用、已纳入后续判断，以及任务结束但未应用。
- `/api/tasks/activity` 返回精简跨项目摘要，包含对话和独立画布任务，省略完整执行轨迹。任务入口位于左侧导航，仅显示和计数状态为 `running` 的任务，点击定位对话或画布节点；排队、待发送、待处理、失败和已停止任务不在此处展示。输入框不再放置任务按钮；待发送消息继续在项目输入框上方管理。
- `TaskRequestInspector.vue` 通过只读 `/api/projects/{id}/tasks/{taskId}/inspection` 查看原请求、关联产物、工具回执状态和本地计费记录。刷新不恢复、不重放、不重新生成；本地没有记录不等于服务商未收费。不确定生成失败不再自动把原请求放回输入框。
- `TaskProgress.vue` 首先显示正在做的事，结束后由 `taskOutcome.ts` 归纳真实交付数量、主要原因和下一步。执行详情在运行中展开、结束后收起；可操作的交付问题置于外层，其余核实和制作提示仍保留在详情。`TaskRequestInspector.vue` 使用原生模态 dialog，提供只读耗时与调用统计，缺少数据不按零展示。未知结果只提供核对入口，明确缺项可手动补齐。
- `XiaojuAvatar.vue` / `xiaojuState.ts` 将思考、制作、等待确认、遇到问题、完成映射到实际任务状态。固定头像框和已注册雪碧图坐标保持位置稳定；首页空闲只轻微眨眼。外观设置“减少动画”持久保存在本机，并尊重系统减少动态效果设置。

以上交互参考 ChatGPT 的运行中追加要求与统一活动入口，结合本产品的持久任务、收费回执和画布并发边界实现：
[长期工作](https://learn.chatgpt.com/docs/long-running-work)、[产品更新](https://learn.chatgpt.com/docs/whats-new)。

验证：`npm run test:interaction-upgrade` 使用构建后的 renderer、临时本地 API、隔离 IndexedDB；不连接真实 Provider 或真实工作区。
