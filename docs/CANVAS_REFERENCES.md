# 画布节点引用

点击图像、文本等已有内容节点，会临时将引用带入左侧对话输入框。连续点击其他资产会累积临时引用；随后单击画布空白处会撤销这一批自动引用，保留原有文字、手动引用和附件。点击或通过键盘聚焦对话输入框、开始编辑或发送后，引用即被保留，之后点击空白处不会移除。空白处框选或平移不算取消引用；画板的“引用布局”等明确引用操作直接保留引用。

连线的方向是「参考素材 → 生成节点」。选择后续节点时，底部输入区会显示直接连接的图像缩略图和文字摘要；链条中更早的输入不会重复展开。只有空白节点显示生成输入框并可被填充；已有内容节点需要作为来源连接到新空白节点，上游和原图节点保留。

- 图像生成可同时选择多张连线参考图，也可加入手动上传的参考图；重复资产只记录一次。Agent 先看图反推并融合需求，纯借鉴仅注入文字，保真沿用与明确改图才向供应商发送原图；详见 `conversation-memory.md` 的图像参考反推与需求融合。
- 文字和网页节点的内容随提示词一起提交，作为生成约束。文本/网页创作也会在任务上下文中收到连接图像。
- 视频最多接受两张有序图像：第一张为首帧、第二张为尾帧，超过两张会在提交前提示调整。音视频文件暂不能直接作为生成参考，需先转换为图像或文字节点。语音生成使用文字参考。
- 未生成内容、正在生成或已经缺失的输入不会被悄悄忽略；输入框提示先准备素材或断开连线。
- 删除、改接、撤销或恢复连线，以及上游产物更新，都会重新计算引用。连线引用不会存入节点的手动上传草稿。
- 前端不允许创建节点到自身的连线；历史自环边不参与生成。后端在 Provider、占位节点和计费前拒绝目标节点或目标资产引用自身，并返回 `self_reference_not_allowed`。

`features/canvasReferences.ts` 为预览和提交提供同一套引用解析。任务保存 `canvasParams` 中的目标、直接输入节点和资产 ID 快照，服务端通过统一图像解析器将本项显式连线参考绑定到生成工具，并校验资产存在、类型和项目范围。模型填写的输出节点若与当前画布输入冲突，返回明确错误；省略输出节点时由系统确定。预检保存本项来源和节点内容版本，正式执行前复核，位置移动不影响校验。`reference_analysis` 决定哪些参考转为文字、哪些需要实际像素；图像适配器向 Images、Chat Completions、Gemini 和 OpenRouter 接口发送经过选择的原图。节点输入提交为 `canvas_node` 独立任务，使用节点级 Session 与锁；不写入左侧对话、项目标题、对话草稿、待发送队列或全局对话运行状态，不同节点可以并行执行。

验证：先 `npm run build`，再 `npm run test:canvas-click-references` 验证画布点击、空白取消、输入确认及实际提交的引用范围；连线与生成使用 `npm run test:canvas-workspace`、`npm exec vitest run apps/renderer/src/features/canvasReferences.test.ts`、`services/api/.venv/bin/python -m pytest services/api/tests/test_canvas_references.py -q`。这些验证使用隔离画布和模拟 Provider，不调用收费模型。
