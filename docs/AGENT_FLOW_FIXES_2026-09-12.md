# Agent 流程修复记录 · 2026-09-12

根据 2026-09-11 的执行流程、模型路由排查和实际 400 错误完成源码修复。本轮没有重新打包或替换已安装的桌面应用，也没有调用真实账户的收费模型。

## 问题与修复

| 排查问题 | 当前处理 |
| --- | --- |
| GPT-5.6 的 Chat 函数工具与推理参数冲突，升档仍失败 | GPT-5/6 默认使用 Responses；显式 Chat 使用 reasoning none；明确协议/鉴权配置错误立即停止无效重试 |
| 简单问候也执行研究、设计、审查并升级模型 | 问候自动 FAST，直接答复；生成任务采用设计与审查；研究类任务才先执行研究 |
| 分类别名、手动模式、HTML/音频缺少产物约束 | 用户意图、节点类型、显式要求独立合并必需产物；不再只依赖分类器的媒体前缀 |
| 审查未通过、无产物或空答复仍可成功 | 增加真实交付检查；审查失败与无效审查 JSON 为失败，保留成果和问题 |
| 视频文件保存后画布回填失败，旧节点转圈并创建重复节点 | 保存回填状态，重试同一本地资产和原节点；读取画布时优先恢复原目标，已有资产节点不重复添加 |
| 视频完成前审查，下载后直接成功 | 视频完成和浏览器检查通过后，仅恢复最终审查；通过后才成功 |
| HTML 只有源码、媒体只判断文件存在 | HTML 沙箱运行和按钮抽查；音频解码；视频解码及最多 3 帧抽取；检查结果绑定内容指纹 |
| 重启丢失工具回执、主 Agent 断线丢失待交付成果 | 从已保存资产、视频 Job 和画布操作的调用标记恢复回执；已有成果继续进入交付等待；未知付费请求仍禁止盲目重发 |
| 产物引用为空、结果用量仅包含末阶段、聊天推进旧工作流 | 根据真实节点与资产建立引用，累计全部阶段及恢复后的用量，普通设计会话不再推进旧版固定工作流 |

## 验证结果

- 后端全量：`python -m pytest services/api/tests -q --tb=short`，**213 passed**。包含真实已安装 Agents SDK、模拟上游传输、SQLite 和画布存储；HTML 等待验收、只恢复审查、失败审查、中断回执恢复均有回归覆盖。

- 真实 Chromium：`npm run test:delivery-preview`，**7 项通过**。正常按钮、有效 WAV、有效 WebM 及 3 帧提取通过；脚本异常、外部脚本拦截、空页面和损坏视频被正确判为失败。

## 使用边界

- HTML、音频、视频的浏览器检查依赖打开对应项目。关闭页面时任务会等待，重新打开后继续，不提前标记完成。
- 内容类型是确定性的交付门槛；数量、布局与语义由审查 Agent 判断。HTML 按钮抽查不是全业务测试，视频抽帧不是逐帧审查，音频解码不是试听。
- 同步审查流程保留一次修订；异步交付恢复后的最终审查失败会明确失败，不重新提交收费生成。
- 本地无法确认是否已扣费的外部请求仍需核对供应商记录，不能承诺跨系统 exactly-once。
- 快速模式仍是起始等级策略，不是严格积分预算；本轮没有增加实时成本/延迟优化，也未扩展 3D、CAD 或任意应用部署。
- GPT-5/6 接口处理已通过模拟兼容回归；中转站实际模型权限与收费生成仍需真实账户联调。
