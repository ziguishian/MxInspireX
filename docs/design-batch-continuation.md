# 对话中的分批设计续接

每个任务在 `input_json.designBatch` 保存本批范围，累计交付项继续保存在 `designPlan.deliverables`。`currentItemIds` 是计划提交中的本批条目；服务端验证后写入 `designBatch.itemIds`。新聊天按项目隔离，浏览器不能提交可信的批次状态。

## 续接路径

1. 入队时读取前一任务的计划、当前批次及真实画布资产。文件缺失、生成中、待修正与已完成分别处理；完成状态不从回复中的数量推断。
2. `resume` 继续未完成项，保持批号和本批范围；`next_batch` 进入下一批；`revise` 修改上一批中的指定条目。明确指令优先，简短“继续”结合上一批实际状态和后续建议判断。
3. 下一批和修改任务先进入 `needs_plan`。Agent 调用 `design_plan` 读取进度与建议，再保存本批清单。下一批使用新 ID，旧项及同一 `scopeId` 下的资产自动保留。修改任务选择旧 ID，并绑定原节点。
4. 计划保存成功后才开放生成。批量调用同样先检查计划和条目范围。旧完成项复用原资产，其他批次的节点不能被本批误覆盖。
5. 生成回执更新真实进度；下一次模型请求独立携带批次意图、状态、执行 ID 和完成节点。恢复使用持久化计划和工具回执，停止在下一批登记阶段不会跳过该批号。

## 进度与验收

- `deliveryProgress`：累计交付状态，携带节点、资产 ID 和内容指纹。
- `designBatch.currentProgress`：本批工作状态。修改尚未执行时，原产物仍计入累计完成，本批显示等待修改。
- 管理界面显示“本批进度”与可折叠的“累计进度”；登记阶段只提示正在整理本批，保留原完成计数。
- 验收的产物和缺项以本批范围为准；累计资产另存于 `cumulativeArtifacts` 用于追溯与去重。
- 旧任务没有批次字段时维持原显示；下一次续接从真实资产重建。取消任务的历史 Skill 绑定可供新任务继承，取消任务本身仍不接受写操作。

## 验证

`test_design_batches.py` 覆盖完成后下一批、未完成续接、原节点修改、停止后续接、旧任务兼容及文件丢失；`test_logo_skill_batches.py` 覆盖三批共十八项。

`test_batch_sdk.py` 使用已安装的 Agents SDK，模拟 Responses 和 Chat Completions 传输，经真实本地工具网关验证“提前调用被拦截 → 登记下一批 → 仅生成新项”。测试不发送真实付费请求。

前端 `taskDelivery.test.ts` 验证两种进度和修改状态；SDK 上下文与生成调度测试验证本批范围在上下文裁剪和批量提交中保持有效。
