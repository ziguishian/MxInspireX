# Windows 0.2.1 → 0.2.2 实际升级记录

日期：2026-10-23。使用正式发布的 Windows x64 完整版 NSIS 包、真实 GitHub 更新源和隔离测试工作区；不调用模型，不使用模拟更新驱动。

## 已验证

- 安装真实 0.2.1，启动后自动提示 0.2.2，显示版本及非商业许可发布说明。
- 点击「稍后更新」后保持 available，无下载；再次打开并点击「立即下载」后进入 downloading，实测进度 14.9%、45.8%、73.9%、97.1%、100%。
- 下载文件 SHA-256：`a49f6caec6fcf2b20f182041291840fab48745b9c6a45ee581f42a0fd203ba80`，与 Release 校验文件一致。
- 下载完成显示「稍后重启 / 立即重启更新」；稍后重启关闭弹窗，仍运行 0.2.1，未自动安装。
- 点击「立即重启更新」退出旧应用，实际启动缓存中的安装包，参数为 `--updated --force-run`。安装向导识别已有当前用户安装；原生窗口输入自动化未生效，由用户继续安装。
- 安装后实际启动的包版本为 0.2.2，根 LICENSE 与仓库非商业许可逐字节一致。
- 在与升级前相同的自动化启动环境重新打开新安装后：项目完整字段、中文节点正文、两个节点、一条连线及项目设置与 before.json 深比较一致；浅色主题和七项常规偏好均保留。
- 0.2.2 自动检测结束为 idle，不弹出更新提示。

## 尚不能判定整条链路全部通过

安装向导结束自动重启时，应用读取默认 `Documents/Langju Design Studio` 工作区，项目列表为空；原测试工作区没有被删除。在原自动化环境重启后，重新读到原工作区及完整设置。

测试由 MSIX 打包的 Codex 启动，存在 `LocalCache/Roaming/MxinspireX` 用户目录重定向；安装程序重新拉起的进程与原自动化启动环境的配置读取行为不同。这是目前观察到的环境差异，不能将「相同启动环境下数据一致」等同于「安装后首次自动重启已验证数据一致」。应在普通 Windows 用户会话直接启动旧版、设置测试数据、完成更新，再验证首次重启。未据此加入跨应用用户目录搜索或自动迁移逻辑。

原安装测试目录尾部为 `installed`，安装后实际运行于 `installed/LangjuAgent`；用户参与了安装向导，尚未独立确认该路径变化来自默认目录处理还是向导选择。
